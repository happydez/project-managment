# Фаза 3. Оценка проекта

Отчёт по фазе 3. Подробности каждого пункта - в отдельных файлах этой папки, все расчёты - в книге [project-estimation.xlsx](project-estimation.xlsx).

## Цель

Оценить проект A1 «Сервис управления системными службами серверов», выбранный в фазе 1: описать use cases, оценить размер и трудозатраты тремя способами (COSMIC Function Points, Use Case Points, коллективная экспертная оценка) и на этой основе сделать выводы о масштабе проекта, команде, сроке и о том, что можно отбросить.

## 1. Use cases

Система состоит из управляющего узла (веб-панель, API, база данных, удостоверяющий центр) и агента на каждом управляемом сервере. Обе части разрабатываются в проекте и находятся внутри границы системы.

Акторы: Администратор и Оператор (веб-панель), Система автоматизации (API), systemd (команды агента), Таймер (расписание).

## 2. COSMIC Function Points

Сервис измерен целиком как одна программа. Выделено 15 групп данных и 32 функциональных процесса, для каждого процесса перечислены перемещения групп данных: Entry, Exit, Read, Write. Каждое перемещение даёт 1 CFP.

| Показатель | Значение |
|------------|----------|
| Размер проекта | 215 CFP |
| Функциональных процессов | 32, в среднем 6.7 CFP, от 3 до 13 |
| По видам перемещений | Entry - 40, Exit - 57, Read - 61, Write - 57 |
| Самые большие use cases | UC10 - 25, UC9 - 24, UC2 - 23, UC7 - 23 |
| Самые маленькие use cases | UC1 - 11, UC11 - 12, UC12 - 12 |

Размер распределён по use cases ровно, от 5% до 12%. Чаще всего перемещается запись аудита: 34 перемещения в 26 процессах из 32.

Так как сервис измерен целиком, обмен между управляющим узлом и агентом в размер не вошёл. Трудозатраты по CFP не считались: для этого нужна статистика часов на 1 CFP, которой у команды нет.

## 3. Use Case Points

UCP = (UAW + UUCW) × TCF × ECF.

| Показатель | Значение | Как получен |
|------------|----------|-------------|
| UAW | 10 | 5 акторов: два сложных, один средний, два простых |
| UUCW | 135 | 3 сложных use case и 9 средних по числу шагов основного сценария |
| TCF | 1.015 | 13 технических факторов, сумма 41.5 |
| ECF | 0.785 | 8 факторов среды, сумма 20.5 |
| UCP | 115.5 | 145 × 1.015 × 0.785 |
| Трудозатраты | 2311 чел.-ч | 20 часов на 1 UCP |
| | 289 чел.-дней, 14.4 чел.-месяца | |

20 часов на UCP выбраны по правилу Шнайдера и Уинтерса: неблагоприятных факторов среды у нас нет. Оценка включает весь цикл разработки. Она сильно зависит от числа часов на UCP: при 28 часах получилось бы 3235 чел.-ч.

## 4. Коллективная экспертная оценка

Метод - покер планирования с картами 1, 2, 3, 5, 8, 13, 20, 40 человеко-дней. Оценивались 12 use cases и общие работы, не относящиеся ни к одному use case: каркас проекта, канал связи с агентом, развёртывание, сквозное тестирование. Оценки считаются согласованными, если наименьшая и наибольшая карты совпадают или стоят в наборе рядом.

В первом раунде согласие достигнуто по 9 элементам из 13. По UC2, UC10, UC12 и общим работам понадобился второй раунд. Во всех четырёх случаях эксперты по-разному понимали, что входит в элемент.

| Элемент | Чел.-дни | Элемент | Чел.-дни |
|---------|----------|---------|----------|
| UC1 | 3 | UC8 | 2 |
| UC2 | 13 | UC9 | 3 |
| UC3 | 5 | UC10 | 8 |
| UC4 | 5 | UC11 | 5 |
| UC5 | 13 | UC12 | 5 |
| UC6 | 3 | Общие работы | 20 |
| UC7 | 8 | Итого | 93 |

Оценка проекта - сумма оценок элементов: 93 чел.-дня, 744 чел.-ч, 4.7 чел.-месяца. В неё входят проектирование, программирование и модульные тесты.

## 5. Выводы

| Оценка | Чел.-ч | Чел.-месяцы | Что включает |
|--------|--------|-------------|--------------|
| Экспертная | 744 | 4.7 | проектирование, программирование, модульные тесты |
| Рабочая | 1353 | 8.5 | экспертная, достроенная до полного цикла |
| Use Case Points | 2311 | 14.4 | весь цикл разработки |

Оценка в UCP в 3.1 раза больше экспертной: они охватывают разный объём работ, и каждая смещена в свою сторону. Рабочая оценка получена из допущения, что проектирование, программирование и модульные тесты составляют 55% трудозатрат проекта. Оценка в UCP рассматривается как верхняя граница.

Методы по-разному видят use cases. Эксперты считают самыми тяжёлыми UC2 и UC5 (по 17.8% против примерно 10% в COSMIC): в них много технически трудной работы, которую COSMIC не измеряет. Use cases про учётные записи и права (UC6, UC8, UC9), наоборот, в COSMIC весят 26%, а у экспертов 11%.

| Вопрос | Ответ |
|--------|-------|
| Масштаб | небольшой проект: 215 CFP, 115.5 UCP, 12 use cases |
| Трудозатраты | 1350 чел.-ч (8.5 чел.-месяцев), верхняя граница 2300 чел.-ч (14.5 чел.-месяцев) |
| Команда | 5 человек, 4.5 в пересчёте на полную занятость: 2 backend-разработчика, frontend-разработчик, тестировщик, аналитик и руководитель на половину времени |
| Особые требования | знание Linux и systemd, опыт в защите соединений и сертификатах, умение строить стенд из нескольких серверов |
| Срок | около 3 месяцев, до 4 при оценке по верхней границе |
| Что отбросить | работу через API (UC9, UC10) и автоматическое продление сертификата (UC12): минус 28% размера и 17% трудозатрат |

Соображения по распределению:

- Исполнители 15 индивидуальных задач получены решением задачи распределения в фазе 2, а не по договорённости: максимум суммарной предпочтительности при нагрузке от 7.5 до 9.5 ч на участника. Все задачи достались тем, кто оценил их на 4 или 5. От этого распределения не отступали.
- В коллективных задачах участвуют все. Организаторов назначили отдельно: установочную встречу ведёт E2, так как с его задачи начинается работа, покер - E1, так как она его готовила, итоговую встречу - E3.
- Use cases пишут E2 и E4, а сверяет их E1, которая их не писала.

Оценка и факт:

- Фактические трудозатраты - 52 ч при оценке 48 ч, превышение 8%. Из 18 задач 9 заняли столько, сколько оценивалось, 7 заняли больше и 2 меньше.
- Больше всего недооценён покер планирования: по четырём элементам понадобился второй раунд с обсуждением, и сессия заняла 2 ч вместо 1.5 ч у каждого участника.
- Дольше оценки заняли объёмные задачи с большим числом сценариев или строк (use cases, подсчёт COSMIC, выводы, отчёт), быстрее - короткие расчёты по готовым данным (UAW и UUCW, агрегация экспертных оценок).
- Фактическая нагрузка участников осталась близкой: от 11.5 до 14.5 ч.
